# 直播切片 · 竖屏高光切片 SOP

> 读者：要把 1–4 小时直播录播拆成竖屏短视频的人或执行 Agent。目标：从高光筛选到交付 ≤2.5 小时/条（按 180s 基准折算），片段能独立看懂、不失真、不惹授权麻烦。

## 适用 / 不适用

| 适用 | 不适用（改用什么） |
|---|---|
| 有直播录播源，要拆成 15–90s 竖屏高光 | 没有录播源、要现场拍 → [口播知识](short-oral-knowledge.md) |
| 带货讲解、知识直播、访谈型直播的金句切片 | 需要多段素材按音乐节奏拼 → [混剪卡点](short-montage-beat.md) |
| 一场直播可批出 10–30 条切片 | 需要完整叙事与生活素材 → [Vlog](short-vlog.md) |
| 已有主播授权、可商用发布 | 未取得主播 / 平台授权，仅内部存档 |

## 交付规格

| 项 | 主规格 | 变体 |
|---|---|---|
| 分辨率 / 画幅 | 1080×1920（9:16） | 原片 16:9 用「模糊背景 + 居中主体」重构，见 S3 |
| 帧率 | 30 fps 恒定 | 原片 25 / 60 fps 先统一到 30 fps |
| 视频编码 / 码率 | H.264 High、level 4.2、VBR 8–16 Mbps（目标 12 Mbps） | 原片码率低时按 8–10 Mbps，不硬拉高清 |
| 音频 | AAC 48 kHz 立体声 192 kbps、-14 LUFS ±1、真峰值 ≤ -1.5 dBTP | 直播现场混响大时先降噪再归一 |
| 字幕 | 烧录大字幕（移动端主流观看） | 平台自动字幕可用时外挂 SRT |
| 封装 / 命名 | .mp4 / `clip-<主播>-<主题>-<日期>-v<n>.mp4` | 同一场直播按序号归档 |
| 时长 | 单高光 15–45s；多段拼接 45–90s | 15–30s 更适合信息流投放 |

## 前置准备

- 素材：直播录播源（1080p 或 720p，尽量用原始录制文件而不是回放下载）、转写稿、切片授权说明。
- 工具：NLE；转写用剪映「智能字幕」或云端 ASR；本机 ffmpeg 9.0.2 做抽音频、竖屏重构、导出（无 libass）。
- 授权：[待确认] 主播授权范围（能不能商用、能不能投流、能不能二创），没确认前只做内部粗剪。
- 目录：`素材/<直播日期>_<主播>/{source,transcript,clips,export}`，每条切片一个子目录。

## 流程总览（阶段 × 产出 × 时间预算）

> 基准：3 分钟（180s）成片、单人操作、转写已就绪。换算：目标时长 T 秒 → 可变工时 ×（T/180），固定工时不变。
> 固定工时 = S0+S6+S7+S8 = 60 min；可变工时 = S1–S5 = 160 min。例：30s 切片 = 60 + 160/6 ≈ 87 min ≈ 1h27m。

## 分阶段操作

### S0 导入与转写

- 用原始录制文件，不要用平台回放（回放已二次压缩且有 UI 水印）。
- 抽音频给 ASR（本机无 whisper，见 [本机环境](../knowledge/环境/environment-local.md)）：

```bash
ffmpeg -i live_20261103.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le live_asr.wav
```

- 转写稿保留时间码，按每 5 分钟切段存 `transcript/part_01.txt`，便于定位与多人并行。

### S1 高光筛选（核心）

- 四个维度各 0–2 分，总分 ≥6 分才进候选；低于 4 分直接放弃。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 独立完整性 | 必须看上下文才懂 | 略需铺垫 | 不依赖上下文可懂 |
| 情绪 / 冲突峰值 | 平铺直叙 | 有小起伏 | 有反转、金句或强情绪 |
| 信息密度 | 15s 内无结论 | 1 个信息点 | ≥1 个可带走结论 + 论证 |
| 视觉可用 | 遮挡 / 切屏 / 敏感 | 可用但构图差 | 主播在画面、无遮挡 |

- 快速法：先在转写稿里搜金句 / 数字 / 「记住」「千万」「最」等信号词，再回看前后 10–20s 确认上下文。
- 反例：断章取义制造冲突（有舆情风险）、纯商品口播无信息（完播差）、从句子中间开始（观众懵）。

### S2 切片边界确定

- 时长：单高光 15–45s；同主题多段拼接 45–90s。先按 30s 剪，超了再拆，不要一上来做 90s。
- 开头 0.5–1.5s 内抛结论 / 金句（前置钩子），结尾 0.5–1s 收束；不要留长停顿和「嗯、那个」。
- 一条切片只讲一件事；出现第二个信息点就另起一条。
- 输出：区间表 `切片编号 | 起止时间码 | 一句话标题 | 评分 | 素材位`。

### S3 竖屏重构

- 原 16:9 → 9:16 两种做法：人物居中可裁切（放大 ≤1.4×）；裁切会切到人就用模糊背景填充。
- 模糊背景命令（本机实测 2026-11-03，退出码 0）：

```bash
ffmpeg -hide_banner -y -i clip_source.mp4 -filter_complex "[0:v]split=2[bg][fg];[bg]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=20:2[bgb];[fg]scale=1080:-2[fgs];[bgb][fgs]overlay=(W-w)/2:(H-h)/2,format=yuv420p[v]" -map "[v]" -map 0:a? -c:v libx264 -preset slow -crf 20 -c:a aac -b:a 192k clip_916.mp4
```

- 构图：人脸在上 1/3 线附近，头顶留 8–10%；下方 300 px 留给字幕，上方 200 px 不放关键信息。
- 去掉直播 UI：聊天框、礼物特效、平台水印——能裁掉就裁，裁不掉用模糊/遮挡，不要保留他人隐私信息。

### S4 字幕与大字报

- 大字幕：单行 ≤10 字、每屏 ≤2 行，字号 72–96 px；关键词单独放大或用色块，1 条切片 ≤3 处。
- 金句卡：1–2 个/条，停留 1.5–2.5s；位置在中部偏上，避免与字幕抢位置。
- 烧录两条路：NLE 烧录（Premiere「导出 → 媒体 → 字幕 → 烧录」、达芬奇「交付 → 字幕 → 烧录」）；或用 [口播 SOP 的 Pillow 脚本](short-oral-knowledge.md) 渲染 PNG + overlay。
- 口头禅处理：转写里删「嗯 / 那个 / 就是说」，画面同步剪掉；删不掉时字幕省略不显示。

### S5 声音修复与响度

- 直播音质常见问题：底噪大、房间混响、音量忽大忽小。顺序：降噪（≤50%）→ 高通 100 Hz → 压缩 3:1 → 齿音压制 6–8 kHz。
- 不要把人声修成「真空」：保留 -20 dB 左右环境声，否则观众觉得假。
- 响度：-14 LUFS、真峰值 -1.5 dBTP；先测量：

```bash
ffmpeg -hide_banner -nostats -i clip_mix.wav -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null - 2>&1 | tail -12
```

### S6 包装与封面帧

- 标题 3–8 字放前 3s；切片封面帧选「有表情 / 有信息 / 有对比」的一帧，不要选说话闭眼的帧。
- 若为带货切片，标注「广告」或合作信息，按平台要求处理。
- 多条切片统一模板：同一场直播的标题条、字体、颜色一致，形成系列感。

### S7 导出

- 命令行（本机实测 2026-11-03：1080×1920 → H.264 High / 12.2 Mbps / AAC 48 kHz）：

```bash
ffmpeg -hide_banner -y -i clip_final.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2,setsar=1" -c:v libx264 -preset slow -profile:v high -level 4.2 -pix_fmt yuv420p -r 30 -b:v 12M -maxrate 16M -bufsize 24M -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart out.mp4
```

- 自查：`ffprobe -v error -show_entries format=duration,bit_rate -show_entries stream=profile,width,height -of compact out.mp4`。

## 质量门禁（QC）

- [ ] 规格：1080×1920 / 30 fps / H.264 High / 8–16 Mbps / AAC 48 kHz 192k / .mp4
- [ ] 时长 15–90s；开头 1.5s 内出现结论或金句
- [ ] 独立可懂：给没看过直播的人看一遍，能说出这条讲了什么
- [ ] 未断章取义：原话上下文完整，无拼贴式扭曲
- [ ] 无直播 UI / 他人隐私 / 平台水印残留
- [ ] 响度 -14 LUFS ±1；无爆音、无忽大忽小
- [ ] 字幕无错别字，单行 ≤10 字，不出安全区
- [ ] 授权可追溯：主播授权、音乐 / 素材授权记录在案

## 常见问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 切片像「半句话」 | 从句子中间起剪 | 往前多留 1–2s 铺垫，或从上一句结论开始 |
| 竖屏后人物太小 | 原片机位远、直接裁切 | 用模糊背景 + 主体放大 1.2–1.4×；仍小就换机位素材 |
| 直播音质救不回来 | 源文件已二次压缩 / 爆音 | 换原始录制文件；爆音段直接不用，别硬修 |
| 被判搬运 / 侵权 | 未取得授权或与他人类似 | 补授权、加自己的解说 / 剪辑结构，不要原样搬运 |
| 高光不够 10 条 | 筛选标准太松或太严 | 先按 ≥6 分放行，再看数据反馈调阈值 |

## 变体（平台 / 时长 / 素材条件）

| 变体 | 差异 |
|---|---|
| 抖音 | 9:16；前 3s 给金句；开放平台建议 ≥720p、mp4/webm（[事实]，来源 2） |
| 视频号 | 9:16；官方建议码率 ≥10 Mbps、手机端 ≤2 GB（[事实]，来源 3）；封面按分享卡片选帧 |
| 小红书 | 9:16 或 3:4；标题党式封面 + 前 3s 结论；体积上限 [待确认] |
| YouTube Shorts | 9:16 或 1:1；2024-10-15 起 ≤3 分钟竖屏归为 Shorts（[事实]，来源 4） |
| 原片 4:5 或 3:4 | 不裁切、上下补模糊边，保证人脸完整 |
| 无竖屏素材 | 直接导出 16:9 加黑边，或按上条补边，不要硬拉变形 |
