# MG 动画工具与 Agent Skill 调研（2026-11-10）

- 目的：判断哪些仓库/库能解决当前「视频内容单调、抓不住注意力」，且能落到现有 Remotion 产线
- 口径：可安装性 / 许可证 / 维护活跃度 / 与 Remotion 的确定性兼容 / 解决的问题 / 接入成本
- 结论：**先接 Onda（组件层）+ 内部 MG 组件；参考 mg-styles-15 / orca / huashu；Lottie 留作 AE 资产通道；Manim 只做数学专项；其余不接。**

## 2. AI Agent Skill 类

### mg-styles-15

- 15 支 10 秒片，每支有完整提示词、画面源码、声音制作；MIT。
- 技术栈：Node + Python + headless Chrome + ffmpeg；3D 风格要 Blender；字体不随仓库分发。
- 对我们：**不是组件库，是风格/提示词/源码参考**。适合解决风格单一：选 2–3 种风格做 attention 参考，不直接 vendor。
- 注意：样片是 10 秒短片，不是 4 分钟课程；复刻要改节奏和字幕。

### orca-motion-skill

- 把产品/数据抽象成格子、横条、卡片、线，做场景内部 MG：依次亮起、折线画出、数字滚动、镜头推近。
- 所有动作在可 seek 时间线上，逐帧录制——这个思路和 Remotion 一致。
- 对我们：**借它的场景内动作语法**，落到我们自己的 CountUp / DrawLine / CardFlip / FocusPush 组件；不必装 skill。

### huashu-motion

- 30 秒商业发布片：先给三个方向，作曲、音效、指帧修改、om check / om qa。
- 对我们：**借它的交付前 QA 和「指着画面改」交互**；引擎不是 Remotion，接入成本高，不建议整体迁移。

### mg-voiceover-animation-generator

- 输入口播/产品图，先判断素材、风格、叙事，输出提示词文档供审阅，确认后生成。
- 对我们：**借「先审提示词/分镜再生成」的流程**；仓库只有 1★，代码成熟度不足，不接。

### vibe-knowledge-film

- 核心不是画风，是「**配图不是讲解**」：每个概念要找外行认得的形象，句子里说到什么屏上就发生什么。
- 对我们：直接命中「内容单调」的根因——不是缺动效，是缺「视觉解释」。**只读参考，许可证不明确，不能 vendor。**

### motion-palette-15

- 16 张风格卡（赛博 HUD、综艺花字、像素、3D 软萌、剪纸皮影），Canvas/Three.js/Remotion 可混用。
- 对我们：风格卡结构值得学；**许可证 NOASSERTION，不复制代码/资产**。

### pixelfx

- 244 个像素特效；除非做像素风，否则与知识/教育视频无关。跳过。

## 3. JavaScript 库

| 库 | 结论 | 原因 |
|---|---|---|
| Anime.js | 不接 | 时间驱动/RAF，Remotion 需要逐帧 seek；会有双时钟 |
| Mo.js | 不接 | 同上；偏 Web 交互 |
| GSAP | 不接 | 强，但时间线/许可/双时钟；不适合当 Remotion 内核 |
| Motion / Framer Motion | 不接 | React 动画，但依赖浏览器时间/手势；Remotion 已有 spring/interpolate |
| Scene.js | 不接 | 2023 后基本停更；时间轴模型重复 |
| Lottie | 需要时接 | AE JSON 的确定性播放；@remotion/lottie 可接 |
| Onda | **立即试** | Remotion 原生、源码复制、70 组件/18 转场、MIT |
| vawe | 观察 | Apache-2.0、Agent-native HTML；但换渲染栈收益不足 |

> 关键判断：**Remotion 是「帧函数」；Anime/Mo/GSAP/Scene/Motion 是「时间驱动」。** 后者不是不能 seek，而是接进来会增加不确定性和两套时间轴。除非有明确收益，不混。

## 4. Python / 数学

- Manim / ManimCE：数学几何、公式、证明最强；MIT。适合「数学第一课」的深水区，但输出是独立视频，需要和 Remotion 合成。**建议做 1 个 15 秒几何片段试验**，不替代主产线。
- PyMotion：1★、许可证 NOASSERTION、生态太新；不接。

## 5. 推荐落地顺序

1. **Onda 试验（1–2 天）**：在独立分支装 5 个组件：count-up、bar-chart、line-chart、spotlight、blur-reveal；验证 Remotion 4.0.540 / React 19 / TS；渲染 10 秒，检查包体、样式冲突、确定性。
2. **内部 MG 组件（2–3 天）**：CountUp、CardFlip、DrawLine、FocusPush、Underline、ChapterCard；这些是我们自己的注意力语法，不依赖 Onda 全量。
3. **应用（1 周）**：先改数学 S2–S4：数字滚动、卡片翻转、数轴点落下、当前卡推近；用 mg-attention-composite 的 4–8s/6.5s 阈值验收。
4. **Lottie（按需）**：有 AE 角色/插画资产时接；没有资产不先上。
5. **Manim（按需）**：只做数学几何/公式片段，渲染后合成；不做主框架。
6. **风格库**：从 mg-styles-15 选 2 个风格做 reference；从 vibe-knowledge-film 借「视觉解释」检查表；不复制未许可代码。

## 6. 不建议现在做

- 不要把 Anime/Mo/GSAP/Scene/Motion 塞进 Remotion 内核；
- 不要整体迁移到 vawe；
- 不要 vendor vibe-knowledge-film / motion-palette-15（许可证不明）；
- 不要为了 MG 引入 Three.js/3D，除非内容真的需要；
- 不要把「加动效」当成「解决单调」：先补视觉解释，再加动效。
