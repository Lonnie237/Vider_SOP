# 单行字幕与持续动效 · 调研与判断

- 日期：2026-11-05
- 问题：观众反馈「文字最好不超过一行」「等语音时画面不动很枯燥」「要不要加 GIF / 线形讲解」。
- 结论先说：**单行字幕是对的；持续动效也是对的，但不是「加 GIF」；底部贯穿线不要（实测抢注意力）；字幕应与旁白字级对齐。**

## 1. 当前 v2 的问题（实测观察）

| 问题 | 证据 | 影响 |
|---|---|---|
| 字幕太长 | 多数旁白句 55–72 字，按 33px 排成 2–3 行 | 违反单行阅读习惯；手机端更明显 |
| 长句停留久 | 一条字幕覆盖 8–12s 旁白 | 观众在「读」和「看」之间来回切换 |
| 画面静止 | 多个 8–15s 段落只有一次入场动画，之后主体几乎不动 | 等待感、枯燥感 |
| 动效集中在开头 | 入场后没有 ambient motion | 语音还在继续，画面已经「死」了 |

## 2. 单行字幕：有明确规范支持

| 来源 | 规则 | 对我们的意义 |
|---|---|---|
| [Netflix 简体中文 timed text 规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide) | **每行 16 个字符**；阅读速度约 9 字/秒（成人） | 商业字幕的硬标准；我们应 ≤16–18 字/行 |
| 在线开放课程微视频字幕制作指南（暨南大学网络与教育技术中心） | **每屏只出现一行，建议每行不超过 20 字** | 中文教学视频的直接依据；支持「单行」 |
| 中文影视字幕惯例 | 常见 12–20 字/行 | 单行 12–16 字最舒服 |
| 阅读速度研究/规范 | 150–180 词/分钟（英文）；中文按 6–9 字/秒 | 一条字幕至少留 0.8–1.2s |

判断：**用户观点正确，但「一行」不是把整句硬压成一行，而是把长句拆成多条短 cue。** 一条字幕 12–16 字，单行；长句拆 2–4 条；每条 1.2–2.5s；不要为了「一行」缩小字号。

## 3. 持续动效：对，但要有「动」的纪律

| 来源 | 观点 | 采用方式 |
|---|---|---|
| [Animation Mentor · Moving Hold](https://www.animationmentor.com/blog/why-all-animators-need-to-master-the-moving-hold/) | 角色保持一个姿势时不能完全冻结，要有细微的 overshoot / 呼吸 / 环境动 | 每个结论停留时保留 1–2 个「活」的元素 |
| 动画十二原则（follow-through / secondary action） | 主动作之后还有次级动作 | 重点动画结束后，留一个慢速尾动 |
| [Kinetic Whiteboard Captions](https://github.com/het8802/opennolan/blob/4457349c386ea1a89c01547f9a76fa650970c131/skills/creative/kinetic-whiteboard-captions.md) | 字幕不是附属品，而是「主角」；按语义节拍逐条出现 | 字幕 cue 与旁白 clause 对齐，逐条出现 |
| Kurzgesagt / 3Blue1Brown / MinutePhysics（案例） | 画面几乎不存在完全静止的 1s；用环境动效、镜头缓推、元素呼吸维持生命感 | 不做「冻结式」停留 |
| [The Dinosaur Impact, Minute by Minute](https://refs.video/v/yt-dFCbJmgeHmA)（案例） | 有一段约 9s 的旁白停顿，靠画面自身推进 | 停顿不是空白，而是让画面说话 |

判断：**不是「一直乱动」，而是「持续但不抢戏」**：
- 环境层（ambient）：网格缓慢漂移、线呼吸、光标闪烁、卡片 1–2px 浮动、进度条走动；
- 焦点层（focus）：关键词出现/变色/连线，按旁白触发；
- 每个镜头至少 1 个 ambient 元素；没有连续 1.2s 的完全静止。

## 4. 要不要加 GIF？

**不建议用 GIF 作为主要动效**：

| 问题 | 说明 |
|---|---|
| 画质 | GIF 256 色，渐变/阴影容易色带，1080p 下明显 |
| 体积 | 同样 3s，GIF 往往比 H.264 大 5–20 倍 |
| 循环 | 循环接缝、速度不可控，和旁白节拍对不上 |
| 授权 | 网图 GIF 来源/授权不清，商用风险 |
| 可控性 | 不能随旁白/数据/主题变色，不能确定性渲染 |

替代：
1. **Remotion/CSS 原生动效**（首选，矢量、可控、确定性）；
2. **Lottie**（需要现成矢量循环时，体积小、可缩放）；
3. 真实录屏/截图 + 缓推/遮罩（需要真实感时）；
4. 实在要 GIF，只做小尺寸装饰，且必须自有版权、控制循环。

## 5. 「线形讲解」：可以做，但不要做底部装饰线

**线形讲解的思路可以用在内容内部**（连接真实节点、对比轴、路径），但不要在全片底部加一条装饰线——实测它会持续抢注意力，像进度条/水印。

如果做，建议：
- 开场：文档下划线 → 变成终端光标；
- 差异段：变成左右对比的中轴线；
- 产品地图：变成连接 CodeBuddy/WorkBuddy、Qoder/QoderWork 的连线；
- 选择段：变成决策路径；
- 结尾：收成一句金句的下划线。

规则：线必须连接真实关系，不能为了动而乱连；线宽 2–3px；只在内容内部出现，不做全片底部常驻线。

## 6. 字幕与旁白精确对齐

- Qwen-Audio-TTS 的 HTTP SSE 接口支持 **word_timestamp_enabled=true**；sentence-end 帧返回每个字的 begin_time/end_time（毫秒）。
- 实现：按 cue 原文的起止字符，换算到字级时间戳；拼接多段音频时加段前 offset。
- 本项目已实现：tools/qwen_tts_ts.py + tools/make_v3_sample_ts.py；v3 样片 20 条 cue 全部按字级时间戳对齐。
- 计费：v3 样片 3 次调用，input 157 / output 389 / total 546 tokens。
