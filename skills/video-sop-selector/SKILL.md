# video-sop-selector · 视频 SOP 路由

## 何时使用

- 用户说「我要做一条短视频 / 宣传片 / 教程 / Vlog…」但没提流程。
- 用户问「这些素材适合做成什么」「怎么剪」「用什么工具」。
- 用户已有 SOP，但不确定平台 / 时长变体用哪套参数。

## 不适用

- 用户已指定 SOP 或技能 → 直接加载对应技能。
- 只需要工具对比 → 读 [能力矩阵](../../knowledge/开源库/能力矩阵.md)。
- 只需要转码参数 → 用 `ffmpeg-render` 技能。
- 需要现成成片 / 代运营 → 超出本技能范围。

## 输入（缺什么问什么，最多问 3 个）

| 字段 | 必问 | 说明 |
|---|---|---|
| 视频形态 / 目标 | 是 | 口播、混剪、切片、Vlog、教程、访谈、宣传片、数据动画 |
| 平台 + 画幅 | 是 | 抖音 / 视频号 / 小红书 / B 站 / YouTube / 客户交付 |
| 时长 | 是 | 目标成片时长区间 |
| 素材条件 | 是 | 实拍 / 录屏 / 素材库 / 纯图表；有无真人出镜；素材量 |
| 自动化预期 | 否 | 手动精剪 / 模板化 / 脚本批量 |
| 截止时间 | 否 | 用于裁剪流程（如跳过精修调色） |

## 步骤

1. 读 [sop/README.md](../../sop/README.md) 的路由表与 [分类体系](../../docs/知识分类体系.md) 的形态表。
2. 按决策顺序判定形态：

```text
有直播录播源，要截高光 ─────────────→ 直播切片
有大量现成镜头 + 音乐驱动 + 情绪/燃点 → 混剪卡点
双人以上对谈 / 播客素材 ─────────────→ 访谈 / 播客
多场景生活记录 + 时间线叙事 ──────────→ Vlog
真人讲解 + 单机位 + 时长 ≤ 3min ──────→ 口播知识
真人讲解 + 步骤演示 + 时长 > 3min ────→ 教程长视频
数据 / 图表为主，无可拍素材 ──────────→ 数据可视化动画
品牌 / 产品卖点 + 高质量素材 ──────────→ 产品宣传片
```

3. 定变体：按平台改画幅 / 时长 / 字幕策略（读 SOP 的「变体」节）。
4. 读对应 SOP 的「交付规格」与「流程总览」，生成执行清单。
5. 检查缺口：素材是否够、工具是否装（参考 [本机环境](../../knowledge/环境/environment-local.md)）、时间是否够。

## 输出格式

```markdown
## 选定 SOP
<形态> → sop/<slug>（理由一句话）

## 交付规格
分辨率 / 帧率 / 音频 / 时长 / 字幕策略

## 前三步
1. <今天就能做的动作>
2. ...
3. ...

## 下一步技能
- <skill-name>：<为什么>

## 风险与前提
- <素材 / 时间 / 工具缺口>

## 假设
- <未确认信息按什么默认值处理>
```

## 失败处理

| 情况 | 处理 |
|---|---|
| 找不到匹配 SOP | 用最接近的一条 + 标注「需新建 SOP」，建议提交任务 |
| 输入信息不足 | 按常见默认值给方案，明确列出假设 |
| 素材不足以支撑形态 | 给降级方案（如混剪 → 口播 + 图文），不硬套 |
| 时间预算明显不够 | 砍非核心环节（调色 / 精包装），保结构与声音 |

## 自检

- [ ] 引用的 SOP 文件真实存在（相对链接可点开）
- [ ] 交付规格与 SOP frontmatter（duration / aspect）一致
- [ ] 输出包含可执行的前三步，不是泛泛建议
- [ ] 明确标注了假设与缺口
