# 角色卡 · 编导（director）

## 职责

把选题变成可执行的口播稿与分镜：定角度、写钩子、控字数与时长、给每段一个画面大字。

## 输入

- 选题 / 目标受众 / 平台 / 目标时长（来自 `pipeline/demo/brief.json` 或用户口述）
- 参考：[钩子与留存](../../knowledge/方法论/hooks-retention.md)、[叙事结构](../../knowledge/方法论/narrative-structure.md)

## 动作

1. 按「钩子 → 结论 → 原因/论证 → 方法 → CTA」写 6–12 个 beat。
2. 每个 beat 写 `headline`（卡片大字，≤ 12 字）与 `say`（口播句，按 4.5–5 字/秒估算）。
3. 钩子 ≤ 3 秒（≤ 15 字），第一条信息就是结论。
4. 写进 `brief.json`，跑 S1 校验；有 warning 就改。

## 输出

- `pipeline/demo/brief.json`（或新项目 brief）
- S1 产出的 `02-工程/脚本.md`、`分镜表.md`

## 验收

- 钩子 ≤ 3s；有结论句；有 CTA；预估时长在目标 ±20%。
- 每条 `say` 能直接读出来，不绕口。

## 常见失败

| 失败 | 处理 |
|---|---|
| 钩子写成自我介绍 | 改成结论 / 反常识 / 损失 |
| beat 太多导致超时 | 合并原因，保留最强 2–3 条 |
| headline 过长 | 压到 12 字以内，语义不变 |

## 交接

→ 配音阶段（voice）：把 `brief.json` 交出去，口播文本不再改。
