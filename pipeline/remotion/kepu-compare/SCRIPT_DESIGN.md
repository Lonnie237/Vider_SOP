| 工作标题 | 《WorkBuddy 和 Qoder，到底差在哪？》 |

## 5. 视觉系统

### 5.1 方向选择

- **方向 A（推荐，延续）**：保留现有深色科技底 + 蓝橙阵营；加入 Graphite Rule Console 的「琥珀章节锚点 + 等宽标签 + 4px 纸感面板」，比现在更克制、更像知识讲解。
- **方向 B（更激进）**：整体换成暖近黑 + 纸张感 + 杂志排版；更「知识区」，但与现有品牌感差异大。
- 本文按方向 A 写规格；方向 B 只需替换 token，结构不变。

### 5.2 Token

| 用途 | 值 |
|---|---|
| Canvas | #0A0E17（不用纯黑） |
| Panel | #111826 |
| Ink | #F4F7FB |
| Muted | #8C97A8 |
| Hairline | rgba(255,255,255,0.08) |
| 腾讯蓝 | #2F7BFF（阵营/内容属性，不做状态） |
| 阿里橙 | #FF6A00（阵营/内容属性） |
| 琥珀 | #F0A93B（章节锚点/当前焦点） |
| 绿 | #3DDC97（推荐/完成） |
| 珊瑚 | #FF6B61（风险/注意） |

颜色纪律：蓝/橙只表示阵营；绿只表示推荐；珊瑚只表示风险；琥珀只做章节锚点与标题竖线，不铺满。

### 5.3 字体与层级

| 用途 | 字体 | 字号 | 备注 |
|---|---|---|---|
| 主标题 | PingFang SC / Noto Sans SC 900 | 96–120px | 1–2 行，最多强调一个词 |
| 大数字/主节点 | 同上 850 | 64–76px | 只放名词/数字 |
| 次级标题 | 同上 800 | 44–56px | 一镜一个 |
| 正文/说明 | 同上 500 | 30–34px | 不写长句 |
| 章节锚点/标签 | JetBrains Mono / Menlo 700 | 20–22px | 01/05 · 定位 |
| 字幕 | PingFang SC 650 | 34px | 2 行以内，关键词变色 |

### 5.4 版式

- 内容左右安全边距 96px；顶部 48px；字幕区底部 58–70px；内容不得进入字幕区。
- 12 列网格；一镜只用一个主构图：左右对比、中心公式、时间线、2×2 矩阵。
- 面板 4px 圆角 + 1px hairline，不用大圆角卡片、不用玻璃拟态、不用重阴影。
- 章节锚点固定左上：琥珀短竖线 + 01/05 + 章节名。
- 屏显不复述旁白，只留名词、关系、结论；同屏关键词 ≤ 3 个。

### 5.5 动效语言

- 每个镜头：命题 → 锚定 → 建构 → 判断 → HOLD；进入 0.30–0.46s，强调只改一个维度。
- 动作只在关键词/句末重音发生；普通解释不逐句飞入。
- 80% 硬切；幕与幕之间 15% 交叉淡化；结尾 5% fade out。
- 禁止：背景漂浮粒子、无意义弹跳、连续两镜同构卡片、动态字重。
- HOLD：每个结论至少停留 0.5–1s，让观众读完。

### 5.6 字幕与声音

- 字幕 2 行以内，34px，底部居中；关键词用阵营色/绿色，不整句高亮。
- 静音友好：屏显标签必须能独立说明当前对比；不依赖旁白才能看懂。
- 默认无 BGM；如加，仅 -30dB 环境垫，旁白出现时 duck 到 -34dB。
- SFX 只用于 6 类节点：键盘、翻页、whoosh、click、成功提示、低频落定；不堆音效。
- 旁白：龙安灵心 longanlingxin_v3.1，speech_rate=1.05；目标 -16 LUFS。

## 11. v3 视觉修订：单行字幕 + 持续动效（待执行）

### 11.1 字幕：一屏一行，12–16 字

- 不再用「整句旁白」做字幕；把每条旁白拆成 2–4 条短 cue。
- 单行 12–16 字（硬上限 18–20）；字号 34–40px，不为塞字缩小。
- 每条 cue 停留 1.2–2.5s；阅读速度 ≤ 8 字/秒。
- 视频内是「关键词 cue」，另出完整 SRT。

示例（S7 原句 70 字）：

| 原句 | 拆成 cue |
|---|---|
| 那为什么两家各推一款？因为腾讯有 CodeBuddy 管编程、WorkBuddy 管办公；阿里有 Qoder 管代码、QoderWork 管办公。不是重复造轮子，是同一能力的两条产品线。 | 那为什么两家各推一款？ / 腾讯：CodeBuddy 管编程 / WorkBuddy 管办公 / 阿里：Qoder 管代码 / QoderWork 管办公 / 不是重复造轮子 / 是同一能力的两条产品线 |

### 11.2 动效：环境层 + 焦点层

| 层 | 内容 | 规则 |
|---|---|---|
| 环境层 | 网格漂移、渐变光斑、章节线呼吸、光标闪烁、进度条 | 全片常驻；0.05–0.3Hz；1–3px |
| 焦点层 | 标题落位、卡片入场、数字滚动、连线、关键词变色 | 只在关键词/句末重音；≤1 个/句 |
| 字幕层 | 字级时间戳对齐 | Qwen TTS word_timestamp_enabled=true；cue 精确 start/end |

每个镜头至少 1 个环境层元素；结论 HOLD 时保留轻微呼吸，避免冻结；无连续 1.2s 完全静止。

### 11.3 不做底部装饰线

- 实测底部贯穿线会抢注意力，像进度条/水印；v3 起删除。
- 需要连续性时，用内容内部的连线/路径，不新增全片底部线。

### 11.4 字级对齐

- Qwen TTS 传 word_timestamp_enabled=true，拿 sentence-end 的逐字 begin/end。
- cue 记录原文起止字符 → 换算精确 start/end；多段拼接加段前 offset。
- 没时间戳时才退回按字数插值，并标注。

### 11.4 不用 GIF

GIF 的色带、体积、循环接缝、授权与不可控问题明显；改用 Remotion/CSS 原生动效，复杂矢量循环可用 Lottie。

### 11.5 v3 验收

- 100% 字幕单行、≤18 字；无一条字幕停留 <0.8s。
- 抽 5 个 10s 窗口，无连续 1.2s 完全静止。
- 静音观看能跟上 80%。
- 每条字幕与旁白吐字对齐；不出现「字还没读到就换」或「读完还挂着」。

### 11.6 实施顺序

1. 先重做字幕 cue（不改旁白音频），预览 30s；
2. 再加环境层与线形层；
3. 最后处理焦点动效与转场；
4. 全片渲染 + QC。
