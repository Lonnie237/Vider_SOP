## 1. 分支与提交

- 主分支 `main`：始终通过 `validate --strict`、索引最新、`healthcheck`。
- 小改动直接提交 main；结构性改动建议开分支 `feat/<topic>`，PR 合并。
- 提交信息：`feat|fix|docs|chore(scope): 说明`；一次提交一件事。
- 不提交媒体、运行产物、凭据（见 `.gitignore`：`pipeline/runs/`、`.secrets/`）。

## 2. 认证（部署密钥）

本机使用**仓库级 Deploy Key**（只授权这一个仓库，不占用账号 SSH key）：

- 私钥：`.secrets/vider_sop`（已 gitignore，权限 600）
- 公钥：`.secrets/vider_sop.pub`
- Git 配置：`core.sshCommand` 固定使用该私钥，`IdentitiesOnly=yes`
- GitHub 侧：仓库 Settings → Deploy keys → 添加公钥并勾选 **Allow write access**

换机/轮换：

```bash
# 生成新密钥（仓库根目录）
ssh-keygen -t ed25519 -f .secrets/vider_sop -N "" -C "vider-sop-agent"
cat .secrets/vider_sop.pub        # 贴到 GitHub Deploy keys（勾选 write）
git config core.sshCommand "ssh -i $(pwd)/.secrets/vider_sop -o IdentitiesOnly=yes -o UserKnownHostsFile=$(pwd)/.secrets/known_hosts -o StrictHostKeyChecking=accept-new"
```

> 也可用 fine-grained PAT（Contents: Read/Write）走 HTTPS；token 只放 `.secrets/github_token`，不要贴到聊天或提交。
