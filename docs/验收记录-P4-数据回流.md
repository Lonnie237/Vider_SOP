# P4 · 数据回流（机制验证）

- 日期：2026-11-13
- 目标：把发布数据变成“下一版改什么”的判断
- 结论：**回流链路已跑通；当前用示例数据验证，尚无真实投放数据**。

## 1. 数据格式

放在项目运行目录：<run>/_pipeline/retro-data.json

    {
      "published_at": "2026-11-13",
      "platforms": ["视频号", "小红书"],
      "baseline": {"usage": 131},
      "metrics": {
        "views": 1200,
        "completions": 260,
        "asset_opens": 25,
        "workbuddy_opens": 6,
        "first_tasks": 2
      }
    }

示例文件：pipeline/demo/retro-data.example.json（明确标注示例，不代表真实投放）。

## 2. 漏斗与判断

| 指标 | 算法 | 阈值 |
|---|---|---|
| completion_rate | completions / views | <30% → 改钩子/节奏 |
| asset_open_rate | asset_opens / views | <1% → 改钩子/封面 |
| workbuddy_open_rate | workbuddy_opens / asset_opens | <20% → 改 CTA/资产页首屏 |
| first_task_rate | first_tasks / workbuddy_opens | <30% → 改演示/上手 |

- views < 100：样本不足，不下结论；
- 无问题：判断“保持”。

## 3. 集成

- 新增 pipeline/retro_data.py：校验、算漏斗、给判断与动作；
- pipeline/board.py --retro：自动读取 retro-data.json，写入“数据回流”节；
- 没有数据时明确写“未接入”，不伪造。

## 4. 示例验证

示例数据（1200 播放 / 260 完播 / 25 资产页 / 6 WorkBuddy / 2 首次任务）：

- completion_rate 0.2167 → 低于 30%；
- 判断：**需要改：完播低**；
- 动作：前 3 秒先给结论，删掉铺垫；或把片长压 20%。
