# 质量门禁

> 门禁的目的：让「做完」有客观标准，让 Lead 验收不靠感觉，让多 Agent 产出可比较。

---

## 1. 三级质量

| 等级 | 定义 | 客观要求 | 谁可以标 |
|---|---|---|---|
| 草稿 | 结构在，内容待验证 | frontmatter 合法；必备节齐全；缺口明确标注 | 任何 Agent |
| 可用 | 别人照着能干活 | 来源可查；无死链；有可执行示例 / 步骤；参数完整 | 作者自评 + Lead 抽检 |
| 已验证 | 本机 / 真实项目跑通 | 有 `[实测]` 记录（日期 / 环境 / 命令 / 结果）；结论可复现 | Lead 确认 |

> 默认新条目为「草稿」；同一批里「可用」比例 ≥ 80% 才算这批交付合格。

---

## 2. 自动门禁（机器判）

```bash
python3 scripts/validate.py            # 0 error 才能提交
python3 scripts/build_index.py --check # INDEX.md 必须最新
python3 scripts/healthcheck.py         # 一键体检：门禁 + 索引 + 计数 + 流水线 + Git
```

脚本检查项：

| 检查 | 级别 |
|---|---|
| frontmatter 可解析、必填字段齐全 | error |
| `id` 唯一、格式正确、与文件名一致 | error |
| `status` / `confidence` / `difficulty` 取值合法 | error |
| `updated` 为 `YYYY-MM-DD` | error |
| 库/工具条目缺 `repo` / `license` / `language` / `platform` | error |
| 仓内相对链接指向不存在的文件 | error |
| 出现裸 `TODO` | warning |
| 出现「待补充」但无说明 | warning |
| 技能 `SKILL.md` 缺 `name` / `description` | error |
| `INDEX.md` 与内容不一致 | error（--check 时） |

## 3. 人工门禁（按类型）

### 3.1 库 / 工具条目

- [ ] 定位一句话说清「它是什么 + 为谁解决什么」
- [ ] license 写清（含 GPL 传染性风险提示）
- [ ] 维护状态：最近发布 / 提交活跃度（标来源与日期）
- [ ] 最小示例：安装命令 + 一条可跑的命令 / 代码
- [ ] 坑位：至少 2 条真实限制（性能 / 兼容 / 学习成本）
- [ ] 与替代品的关系：什么时候不用它
- [ ] 能力矩阵中已登记（库条目任务要求）

### 3.2 方法论条目

- [ ] 有判断标准（多少算好 / 什么情况算坏）
- [ ] 有可操作步骤，不只是概念
- [ ] 有反例（常见错误做法）
- [ ] 有验证方式（怎么知道做对了）
- [ ] 引用具体 SOP / 库作为落地接口

### 3.3 SOP

- [ ] 适用 / 不适用边界清楚
- [ ] 交付规格可执行：分辨率、帧率、码率 / 质量档、音频响度、封装、命名
- [ ] 流程总览含阶段产出与时间预算
- [ ] 每阶段有关键参数与常见返工点
- [ ] 有 QC 清单且可逐条检查
- [ ] 有可自动化环节（FFmpeg / API / 批量脚本）
- [ ] 变体节覆盖主要平台差异

### 3.4 技能包

- [ ] `description` 写清触发条件（Agent 能判断何时用）
- [ ] 有输入 / 输出定义
- [ ] 步骤可执行，命令可直接跑
- [ ] 失败处理：依赖缺失、路径不存在、参数越界怎么办
- [ ] 自检步骤（跑什么命令确认成功）
- [ ] 不重复知识库大段内容，改为引用

## 4. Lead 验收流程

1. 收任务卡 → 看产出文件清单。
2. 跑 `validate.py` → 0 error；warning 逐条看。
3. 抽检：每类至少 1 条按「人工门禁」全过。
4. 抽查事实：随机 3 条外部事实，点开来源验证。
5. 检查跨条目一致性：id、术语、参数（如响度统一 -14 LUFS）。
6. 通过 → 卡片标记 completed；不通过 → 写具体返工项（文件 + 节 + 要求），重新派发。

---

## 5. 常见返工原因

| 现象 | 根因 | 处理 |
|---|---|---|
| 条目像百科 | 没按「能照着干」写 | 补示例、参数、坑位，砍掉背景介绍 |
| 参数到处不一致 | 没引用公共工作流条目 | 抽到工作流条目，SOP 引用 |
| 链接失效 | 用了会变的 URL | 用官方稳定页；标注访问日期 |
| 版本号对不上 | 凭记忆写 | 查 release / 官方文档，标来源 |
| 大量「待补充」 | 赶进度 | 要么补，要么明确写缺什么、谁补、何时补 |

---

## 6. 质量指标（每轮统计）

- 条目总数 / 「可用」以上占比 / 「已验证」数
- error 数、warning 数
- 覆盖矩阵缺口数
- SOP 端到端实测通过数

> 目标：P1 结束「可用」≥ 80%；P2 结束至少 2 条 SOP 有端到端实测记录。
