# 知识分类体系

> 目标：**任何一条视频制作知识，30 秒内能被放到唯一正确的位置**；任何一条 SOP 都能被检索、被引用、被 Agent 执行。

---

## 1. 三条分类轴

### 轴 A：内容类型（决定目录与模板）

| 类型 | 目录 | 回答的问题 | 模板 |
|---|---|---|---|
| 库 / 工具 | `knowledge/开源库/` | 用什么做？怎么装？能做到什么程度？坑在哪？ | [知识条目-开源库](../templates/知识条目-开源库.md) |
| 方法论 | `knowledge/方法论/` | 为什么这样做？判断标准是什么？ | [知识条目-方法论](../templates/知识条目-方法论.md) |
| 工作流 | `knowledge/工作流/` | 跨环节怎么串？参数与规范是什么？ | [知识条目-方法论](../templates/知识条目-方法论.md) |
| 环境 | `knowledge/环境/` | 本机 / 目标机器有什么？性能与容量边界？ | [知识条目-方法论](../templates/知识条目-方法论.md) |
| SOP | `sop/` | 某类视频从 0 到交付，按什么顺序、什么参数做？ | [SOP](../templates/SOP.md) |
| 技能 | `skills/` | Agent 遇到什么触发条件时，按什么步骤执行？ | [skills/README.md](../skills/README.md) |
| 调研 | `research/` | 结论从哪来？来源与验证过程？ | [research/README.md](../research/README.md) |

### 轴 B：制作环节（标签与检索维度）

```text
S0 选题与策略 → S1 脚本与分镜 → S2 拍摄与素材采集 → S3 素材管理与整理
→ S4 粗剪（结构） → S5 精剪（节奏/表演） → S6 声音（对白/音乐/音效/混音）
→ S7 字幕与图文 → S8 调色 → S9 动效与包装 → S10 导出与交付 → S11 质检与复盘
```

每条知识必须标注主要服务的环节（`domain` 字段，可多值）。

### 轴 C：视频形态（决定用哪条 SOP）

| 形态 | 典型时长 | 画幅 | SOP |
|---|---|---|---|
| 口播知识（知识分享 / 观点） | 30–180s | 9:16 / 16:9 | [short-oral-knowledge](../sop/short-oral-knowledge.md) |
| 混剪卡点（情绪 / 燃向） | 15–60s | 9:16 | [short-montage-beat](../sop/short-montage-beat.md) |
| 直播切片（高光 / 带货） | 15–90s | 9:16 | [short-live-clip](../sop/short-live-clip.md) |
| Vlog（生活 / 旅行） | 3–15min | 16:9 / 9:16 | [short-vlog](../sop/short-vlog.md) |
| 教程长视频（知识 / 软件） | 5–30min | 16:9 | [long-tutorial](../sop/long-tutorial.md) |
| 访谈 / 播客视频 | 20–120min | 16:9 | [long-interview-podcast](../sop/long-interview-podcast.md) |
| 产品宣传片 | 30–120s | 16:9 / 9:16 | [long-promo](../sop/long-promo.md) |
| 数据可视化动画 | 30–180s | 16:9 / 9:16 | [long-data-animation](../sop/long-data-animation.md) |

> 新形态进入条件：有稳定产出需求 + 与现有形态流程差异 ≥ 30%。否则扩展现有 SOP 的「变体」节。

## 2. ID 与命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 知识条目 id | `kb/<slug>`，slug 与文件名一致 | `kb/ffmpeg` ↔ `knowledge/开源库/ffmpeg.md` |
| SOP id | `sop/<slug>` | `sop/short-oral-knowledge` |
| 技能名 | 目录名 = frontmatter `name`，小写 kebab-case | `video-sop-selector` |
| 文件命名 | 小写英文 + 连字符，不用空格 / 下划线 / 中文 | `long-data-animation.md` |
| 标题 | 中文，格式「对象 · 一句话定位」 | `FFmpeg · 音视频处理瑞士军刀` |

例外：目录名、模板文件名可用中文便于人读；条目文件名必须英文。

维度：环节（S0–S11）× 内容类型。✅ 已有「可用」以上条目，◐ 仅草稿，· 缺口。

| 环节 | 库 / 工具 | 方法论 | 工作流 | SOP |
|---|---|---|---|---|
| S0 选题 | · | ✅ hooks-retention | · | 各 SOP 内联 |
| S1 脚本分镜 | · | ✅ narrative-structure | · | 各 SOP 内联 |
| S2 拍摄 | · | · | · | 各 SOP 内联 |
| S3 素材管理 | · | · | ✅ asset-management | 各 SOP 内联 |
| S4–S5 剪辑 | ✅ ffmpeg / moviepy / pyav / auto-editor | ✅ pacing-beat | ✅ automation-pipeline | 各 SOP 内联 |
| S6 声音 | ✅ ffmpeg | ✅ sound-design | · | 各 SOP 内联 |
| S7 字幕 | ·（whisperx 待补） | ✅ subtitle-density | · | 各 SOP 内联 |
| S8 调色 | · | ✅ color-grading | · | 各 SOP 内联 |
| S9 动效包装 | ✅ remotion | · | · | 各 SOP 内联 |
| S10 导出交付 | ✅ ffmpeg | · | ✅ transcode-delivery | 各 SOP 内联 |
| S11 质检复盘 | · | · | ✅ transcode-delivery / platform-specs | 各 SOP 内联 |

**横切**：环境 [environment-local](../knowledge/环境/environment-local.md)；技能 [skills/](../skills/README.md)（sop-selector / project-init / ffmpeg-render / subtitle-pipeline / qc-deliver）。

## 4. 粒度标准

- **一个工具一条**：`ffmpeg`、`moviepy` 分列，不写“十大剪辑库”。
- **一个方法一条**：`钩子与留存`、`卡点与节奏` 分列。
- **一条 SOP 覆盖一种交付形态**：平台差异写「变体」节，不复制整条 SOP。
- **跨条目复用**：公共步骤（代理剪辑、字幕烧录、导出参数）沉到工作流条目，SOP 只写「按 [xx] 执行 + 本形态特有参数」。

---

## 5. 扩展与归档

1. 新工具：先加条目（草稿）→ 进能力矩阵 → 有实测后升「可用 / 已验证」。
2. 新方法：必须有可操作步骤与反例，否则不建条目，先放 `research/` 笔记。
3. 新形态：先建 SOP 骨架 + 路由表条目 + 模板适配，再补知识。
4. 归档：`status: 归档`，条目顶部写替代方案与归档原因，保留历史不删除。
