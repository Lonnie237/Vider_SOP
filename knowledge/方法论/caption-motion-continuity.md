# 单行字幕与持续动效 · 不让画面「死」的规则

## 一句话定位

字幕**一屏一行、12–16 字**，长句拆成多条短 cue，并用 TTS 字级时间戳让每条字幕与吐字精确对齐；画面在每个停留段保留「持续但不抢戏」的环境动效——让观众在「等旁白」时也有东西可看，但不被乱动干扰。

## 适用场景

- 45–120s 科普/知识/产品讲解视频。
- 16:9 横屏、9:16 竖屏都适用；竖屏字幕更短（10–14 字）。
- 尤其适合「旁白为主、画面为辅助」的代码化视频（Remotion / HyperFrames）。
- 不适用：纯实拍对话、字幕必须完整转录的访谈（用两行/完整字幕规范）。

## 原理与判断标准

1. **阅读与观看是两条通道**：字幕越长，观众越容易「读字忘画」；单行短 cue 把注意力还给画面。
2. **字幕不是旁白全文**：旁白负责因果，字幕只保留关键词/短句；完整转录另出 SRT。
3. **静止会「死」**：完全冻结的画面会让观众意识到「在等」；moving hold 用 1–2px 的呼吸/漂移维持生命感 [实测+推断]。
4. **动效要分层**：环境层持续、低幅；焦点层按关键词触发；两者不抢戏。
5. **底部装饰线不要**：实测底部贯穿线会抢注意力；需要连续性时，用内容内部的连线/路径，而不是全片底部加一条线。
6. **动效服务理解**：每个可见动作都要能回指到当前旁白落点；不能为了「不枯燥」而乱加。
7. **视觉元素按词揭示**：不要句首一次性全出；元素在锚点词前 80–150ms 进入，旁白读到它时画面刚好接上。

## 可操作步骤

### 1. 拆字幕 cue（单行）

1. 先按语义/标点把旁白切成 8–16 字的短句。
2. 每条 cue 只表达一个信息点；不要把两个逗号句硬塞进一行。
3. 一条 cue 停留 1.2–2.5s；最短不低于 0.8s；阅读速度 ≤ 8 字/秒。
4. 字号不因「想塞进一行」而缩小；塞不下就再拆一条。
5. 字幕与 SRT 分离：视频内是「关键词 cue」，SRT 是完整旁白（供静音/无障碍）。

示例（原句 28 字）：
- 原句：WorkBuddy 读的是文档、表格、会议纪要，还有腾讯文档和企业微信。
- 拆成："WorkBuddy 读文档" / "表格、会议纪要" / "还有腾讯文档、企微"。

### 2. 加持续动效（两层）

- **环境层（全片常驻）**：背景网格缓慢漂移（0.05–0.1Hz）、渐变光斑 10–20s 周期、章节线 1–2px 呼吸、光标闪烁（1s 周期）、进度条匀速。
- **焦点层（按关键词）**：标题落位、卡片入场、数字滚动、连线 CONNECT、关键词变色、状态 CHECK。
- 每个镜头至少 1 个环境层元素；焦点层动作 ≤ 1 个/句。
- 结论停留（HOLD）时，保留环境层 + 一个 0.2–0.3Hz 的轻微呼吸，避免冻结。

### 3. 字幕与旁白精确对齐

- 用支持字级时间戳的 TTS（如 Qwen-Audio-TTS 的 word_timestamp_enabled=true），拿到每个字的 begin/end。
- 每条字幕 cue 记录原文起止字符，用字级时间戳换算出精确 start/end，不按字数插值。
- 拼接多段音频时，给每段加上段前 offset；字幕时间 = 段 offset + 字级时间。
- 没有字级时间戳时，才退回「按字数比例」的近似，并标注风险。

### 4. 视觉元素按词揭示（Anchor Map）

- 给每个视觉元素绑定一个**旁白锚点词**（如「企业微信」「PR」「QoderWork」）。
- 元素进入时间 = 锚点词 begin_time − 80–150ms；不要句首全出。
- 同一句最多 2–3 个元素变化；其余元素等下一句。
- 当前词高亮；已说过的词保持中性；未说的词不提前亮。
- 没有字级时间戳时，才按句/短语近似，并标注风险。

### 5. 每镜自检

- 这一镜有没有连续 1.2s 完全静止？
- 视觉元素是不是句首就全出？应该跟着锚点词逐个出现。
- 内容重心是否偏上/底部空？主体应在画面中段（约 20%–75% 高度）。
- 字幕是否一行、≤16–18 字？
- 动效是否只在关键词发生？
- 线/动效是否指向真实关系，而不是装饰？

## 参数与阈值

| 参数 | 推荐值 | 依据 |
|---|---|---|
| 中文单行字幕 | 12–16 字（硬上限 18–20） | Netflix 简体中文 16 字/行；教学视频指南单行≤20 字 |
| 竖屏字幕 | 10–14 字 | 屏幕更窄，安全区更大 |
| 阅读速度 | 6–8 字/秒 | 低于 9 字/秒的规范上限 |
| 单条 cue 时长 | 1.2–2.5s | 阅读 + 呼吸 |
| 完全静止上限 | ≤1.2s | 超过就像「卡住」[推断] |
| 环境动效频率 | 0.05–0.3Hz | 慢、不抢戏 |
| 环境动效幅度 | 1–3px / 0.5–1.5% | 可感知但不干扰阅读 |
| 焦点动作 | ≤1 个/句 | 防止注意力过载 |
| 字级对齐 | 每条 cue 有精确 start/end | 字级时间戳，不按字数插值 |
| 视觉元素预演 | 锚点词前 80–150ms | 先看到、紧接听到 |
| 元素进入时长 | 0.2–0.3s | 不拖沓 |
| 内容重心 | 画面 20%–75% 高度 | 避免顶部堆叠、底部空洞 |

## 常见反例

| 反例 | 为什么不行 | 怎么改 |
|---|---|---|
| 整句 50–70 字压成一行/两行 | 阅读速度超标，观众读字忘画 | 拆成 2–4 条短 cue |
| 为了单行把字号缩到 24px | 手机端看不清 | 保持 34–40px，拆句 |
| 全片加 GIF 循环 | 画质/体积/循环接缝/授权问题 | 用 Remotion/CSS/Lottie |
| 每个元素都在动 | 注意力过载，像 PPT 动画 | 环境层 + 焦点层分离 |
| 动效和旁白无关 | 观众不知道看哪 | 动作只在关键词/句末重音 |
| 底部贯穿线 | 抢注意力，像进度条/水印 | 删掉；需要连续性时用内容内连线 |
| 静止 HOLD 超过 2s | 观众以为卡了 | 加呼吸/漂移/光标 |
| 句首全部元素出现 | 读到关键词时画面已演完 | 按锚点词逐个揭示 |
| 内容全堆在顶部 | 底部空、重心不稳 | 主体下移/居中，底部用信息条承接 |

## 验证方式

- 抽 10 条字幕，统计字数/行数/停留时长；目标 100% 单行、≤18 字。
- 抽 5 个 10s 窗口，检查是否有连续 1.2s 静止；用帧差/目测。
- 静音观看一遍：只看画面能否跟上 80%。
- 检查动效是否都能回指当前旁白；不能回指的动作删掉。
- 检查线是否连接真实关系；无意义线段删掉。
